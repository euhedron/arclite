What the gate runs is configuration, not shell: settings declare the gate's steps — audit, align, the advisories, the meta-audits, each on or off with built-in defaults and its scope — read by an `arc gate` command the hook shells out to, so `.arc/hooks/pre-push` collapses to a one-line shim and gate composition is set like any setting (CLI and TUI), never by editing bash. The no-parallel-config principle is honored at its actual boundary — duplication: the configured steps are the composition's single home, read by `arc gate` and restated nowhere (the shim names no verbs, so there is no second statement to rot — the ruleset pattern applied to the gate), and the full shell hook remains available to anyone wanting shell-level control (the configured gate is the default posture, not a cage). The same configured gate definition is then what CI invokes, so the local hook and the CI check can't drift.
