What the gate runs is configuration, not shell: settings declare the gate's steps — audit, align, the advisories, the meta-audits, each on or off with built-in defaults and its scope — read by an `arc gate` command the hook shells out to, so `.arc/hooks/pre-push` collapses to a one-line shim and gate composition is set like any setting (CLI and TUI), never by editing bash. The no-parallel-config-language principle is honored by domain: the gate's steps are arc's own verbs — arc composing arc is arc's surface, not a mirror of a foreign tool's argv — and the full shell hook remains available to anyone wanting shell-level control (the configured gate is the default posture, not a cage). The same configured gate definition is then what CI invokes, so the local hook and the CI check can't drift.
