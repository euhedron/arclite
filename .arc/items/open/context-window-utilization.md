Show context-window utilization — the share of the selected model's window the assembled prompt occupies — in previews, run reports, and TUI views. The measurement reuses the run record's landed scope code at two moments: live on the assembled prompt in a dry-run preview (pre-spend), and stored on the run record after a real run. The token side of the share uses the real token counts where a run has them (a completed run's record carries the billed input tokens) and the labeled 4:1 character approximation where it doesn't (the pre-spend preview), displayed as an approximation (`≈`) in exactly those spots — the share is a display gauge like the estimate it rides on, never an enforcement input. Window sizes come from a built-in model→window table, settings-overridable like any default (the provider model listings don't carry them); warning rides the threshold facility repo-drift-metrics establishes. Its TUI shape includes a last-n-runs **strip**: per-run utilization as segments, boundaries drawn at rounds and commits (gate-round-linkage's ids), each segment carrying its findings count — fluctuation, convergence, and yield in one glance.
