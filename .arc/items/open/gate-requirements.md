Projects declare deterministic requirements the gate checks before any AI step spends — configured in settings, failing the push by naming the unmet condition. Two families, one mechanism. A requirement is a deterministic, judgment-free precondition. Most promote a fact arc *already computes* from merely disclosed to blocking — the agenda-integrity facts the items loader already derives and discloses (coverage — every open item ordered; existence — every ordered id resolves; non-duplication — no id twice), and the presence of a ledger or rules directory a project's discipline assumes — a gate over an existing fact. One adds deterministic machinery arc lacks today: validating a manifest against the `$schema` it declares needs a JSON-Schema validator (a new dependency this item brings), adopted for the confronted case — the euhedron portfolio manifest's published contract. The requirement names the manifest file (a settings-declared path, e.g. `euhedron.project.json`); the schema is the one the manifest's own `$schema` points at, fetched once and cached under `.arc/` (a remote `$schema` is fetched over the same `http::get` path, pinned by content hash so a moved or changed remote schema is a disclosed mismatch, not a silent re-interpretation; offline, a cached schema still validates and a first-fetch failure is the requirement erroring, never passing). Mechanical conformance, needing no judgment. Settings name which already-computed facts block rather than warn, each with its own parameter riding the fact — a presence check's target path, a count threshold — so one existence/count fact serves both "an items ledger exists" and "it holds at least one item" by its threshold alone. Free and instant, so they run first — an AI round never spends against a repo failing its own declared preconditions; align still judges coherence, but mechanical breakage is caught before the judgment spends. Rides gate-configuration's configured gate: requirements are one more declared step kind in the same composition the hook shim and CI both read. Distinct from rules (standards judged over content) and align (agenda coherence): a requirement is checkable without judgment.
