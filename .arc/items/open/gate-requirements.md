Projects declare deterministic requirements the gate checks before any AI step spends — configured in settings, failing the push by naming the unmet condition. Two families, one mechanism. Structural assertions about the repo's shape: an items ledger exists, perhaps non-empty; a rules directory; a manifest that declares a `$schema` validates against it (the euhedron portfolio manifest's published contract is the confronted case — mechanical conformance is a requirement, not a rule, because it needs no judgment); whatever the project's discipline demands. And state-integrity conditions arc already computes deterministically: the agenda's coverage (every open item ordered), existence (every ordered id resolves), non-duplication (no id listed twice), and whatever else the loaders derive — drift facts disclosed ambiently today (doctor's items row, the TUI masthead's warning), which a requirement promotes from disclosed to blocking: the same computation the views read, never a new checker. Free and instant, so they run first — an AI round never spends against a repo failing its own declared preconditions; align still judges coherence, but mechanical breakage is caught before the judgment spends. Rides gate-configuration's configured gate: requirements are one more declared step kind in the same composition the hook shim and CI both read. Distinct from rules (standards judged over content) and align (agenda coherence): a requirement is checkable without judgment.
