Project a repo's run record into the repo — the shape the public-record design discussion settled (the README's open question keeps only the residue). `.arc/record/` as a derived render off the authoritative private ledger: written by an explicit `arc sync`, never in the run hot path; idempotent by run id; an allowlist of fields only — id, timestamp, arc version, verb, backend and model, rules and taxonomy as (id, hash) pairs, gate verdict and blocked/passed, the structured findings and note, commit anchor, and a `format` version — never prompts, absolute paths, or other-repo traces. Cost and token usage (the in/cache/out breakdown `arc usage` sums) are in the format but have two emission profiles, each following its subject: the tracked repo record carries them only under an opt-in setting (publishing spend is a choice), while the CI-artifact instance — uploaded for ledger ingest, never committed — always carries them, because it lands in the operator's private ledger where spend belongs (github-check-gate's `arc usage` line rests on this). Off by default everywhere; arclite opts in as the dogfood and the operator judges the actual emitted record. The same lines are also a serverless team-aggregation substrate.
