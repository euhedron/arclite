Project a repo's run record into the repo — the shape the public-record design discussion settled (the README's open question keeps only the residue). `.arc/record/` as a derived render off the authoritative private ledger: written by an explicit `arc sync`, never in the run hot path; idempotent by run id; an allowlist of fields only — id, timestamp, arc version, verb, backend and model, rules and taxonomy as (id, hash) pairs, gate verdict and blocked/passed, the structured findings and note, commit anchor, and a `format` version — never prompts, absolute paths, or other-repo traces. Cost and token usage join the tracked record only under an opt-in setting — publishing spend is a choice. (Ledger ingest is not this projection's job: CI runs log natively and github-check-gate ingests those `runs.jsonl` lines as-is.) Off by default everywhere; arclite opts in as the dogfood and the operator judges the actual emitted record. The same projected lines are also a serverless team-aggregation substrate — scope boundary: aggregation for a repo's own collaborators via its clones; aggregation beyond one repo's team (across repos, users, orgs) is rulespace-registry's.
