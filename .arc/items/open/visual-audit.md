A visual audit: findings about the UI itself — layout, alignment, disclosure, legibility — judged from literal screenshots of the running TUI. The pieces exist end to end: the committed tape (`assets/arc-tui.tape`) regenerates every surface as PNGs with one command; the claude backend's image reading when granted the `Read` tool is the enabling capability — to be verified in an arc run before anything is built on it, as the first step below does; taxonomies and rulesets are per-run configuration. The first step needs one piece of new machinery and no more: an image-aware context source that enumerates the shots directory and hands the PNGs to the model (the ordinary context walk reads UTF-8 text and `tui-shots/` is gitignored, so images reach no run today). With that, a `ui-feedback` ruleset/taxonomy and a run over the shots directory with a Read grant compose the rest — which is also where the image-reading capability gets its checkable provenance — and the findings' quality decides what more, if anything, arc must grow. The tape doubles as the documentation pipeline: the README's GIF regenerates from it.
