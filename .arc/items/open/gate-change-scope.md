The gate becomes change-aware: a push whose changed paths fall entirely outside a step's declared scope skips that step — skipped loudly, naming the scope that excused it, never silently. The default trigger scope is the scope a step already declares for its context — audit gating on what `--include` feeds it, align on the items ledger — so a manifest-only change spends nothing (exhibited live: the portfolio-manifest push bought a full gate round and a CI audit for a root JSON file no step reads); an explicit gate-ignore list covers paths that never warrant gating. Both are settings, composing with gate-configuration's step declarations (a step's scope serves both what it reads and what triggers it), and CI reads the same declaration — a scope-skipped required check reports satisfied, not absent. The changed set is deterministic, from git's ref range, the same grounding synthesis already draws.
