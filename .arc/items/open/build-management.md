Manage the worktrees `build` produces — build-verb precedes this and produces them; this is the surface for their lifetime. `arc builds` lists each build worktree with its state, derived never stamped: *in flight* (a live run marker), *merged* (the branch tip reachable from the default branch's head), *pending review* (a worktree whose run left a *clean*-completion record — the changeset committed, the run ended without error), else *interrupted* (no clean-completion record — an errored run leaves its errored record, a hard kill leaves nothing, and both mean the build did not cleanly finish). The four states partition on two independent facts — a live marker, and whether a clean-completion record exists — so an errored run (errored record, no clean-completion) lands squarely in *interrupted*, never between states. The commands key on the item id — one live build worktree per item, so the item id names it unambiguously; per-run build ids are ledger history, not worktree handles. `arc builds --resume <item>` relaunches against the same item from the worktree's current on-disk state (its working tree and last commit — continuing the interrupted work, not restarting from base), refusing while that build's run marker is live so a running agent is never double-driven; `arc builds --discard <item>` removes a worktree and its branch; a *merged* build is what `--clean` removes and what resolves the item, the run id in the resolution note. `arc run build` refuses a second worktree for an item that already has one — pointing here to resume or discard it — so re-builds accumulate as ledger run history, never colliding worktrees.
