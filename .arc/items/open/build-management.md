Manage the worktrees `build` produces — build-verb precedes this and produces them; this is the surface for their lifetime. `arc builds` lists each build worktree with its state, derived never stamped: *in flight* (a live run marker), *merged* (the branch tip reachable from the default branch's head), *pending review* (a worktree whose run left a durable completion record — the changeset committed, the run ended clean), else *interrupted* (a worktree with no live marker and no completion record — the absence-based derivation covers an errored run and a hard-killed one alike, since a hard kill writes nothing). The commands key on the item id — one live build worktree per item, so the item id names it unambiguously; per-run build ids are ledger history, not worktree handles. `arc builds --resume <item>` relaunches against the same item from the worktree's current on-disk state (its working tree and last commit — continuing the interrupted work, not restarting from base), refusing while that build's run marker is live so a running agent is never double-driven; `arc builds --discard <item>` removes a worktree and its branch; a *merged* build is what `--clean` removes and what resolves the item, the run id in the resolution note. `arc run build` refuses a second worktree for an item that already has one — pointing here to resume or discard it — so re-builds accumulate as ledger run history, never colliding worktrees.
