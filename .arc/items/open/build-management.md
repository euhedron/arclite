Manage the worktrees `build` produces — build-verb precedes this and produces them; this is the surface for their lifetime. `arc builds` lists each build worktree with its state, derived never stamped: *in flight* (a live run marker), *merged* (the branch tip reachable from the default branch's head), *pending review* (a worktree whose run left a *clean*-completion record — the changeset committed, the run ended without error), else *interrupted* (no clean-completion record — an errored run leaves its errored record, a hard kill leaves nothing, and both mean the build did not cleanly finish). State is of the *current* worktree (one per item), derived from its latest run only — the signals are read in priority order: a live marker, then branch-tip reachability from the default branch, then whether that latest run left a clean-completion record. Earlier runs for the item are ledger history, never state inputs, so a prior clean completion doesn't make an interrupted re-run read as pending-review. The three signals are independent, so every worktree lands in exactly one state: an errored run (errored record, unmerged, no clean-completion) falls through to *interrupted*, never between states. The commands key on the item id — one live build worktree per item, so the item id names it unambiguously; per-run build ids are ledger history, not worktree handles. `arc builds --resume <item>` applies only to an *interrupted* worktree — it relaunches against the same item from the worktree's current on-disk state (its working tree and last commit — continuing the interrupted work, not restarting from base); it refuses an in-flight one (a live marker — a running agent is never double-driven) and a merged or pending-review one (nothing to resume — discard or review it instead); `arc builds --discard <item>` removes a worktree and its branch; a *merged* build is what `--clean` removes and what resolves the item, the run id in the resolution note. `arc run build` refuses a second worktree for an item that already has one — pointing here to resume or discard it — so re-builds accumulate as ledger run history, never colliding worktrees.
