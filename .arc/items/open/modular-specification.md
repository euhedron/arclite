Deconstruct the project's specification into modular parts — facets: the project described as data rather than one prose mass, facets composing sub-facets where scope calls for it, organized by a thin configuration in order.json's spirit (the arranger: `shape.json`, described below) — so reorganizing is a config edit rather than a prose rewrite, and the README (or any view of the project) is an assembled rendering of the parts: the derive-don't-hand-maintain principle applied to the README itself. A project should be fully describable via its specification, and "facet" deliberately names an abstract shape whether or not it is built yet — which is why the README's earlier facts-as-third-concept question resolves into this item ("fact" implied authority; a facet just describes). Typed facets admit a dedicated spec audit — its own vocabulary beside align, rule-quality, and prompt-quality, every artifact class carrying its own quality gate. Draft facets can exist unrendered; per-facet changed-versus-unchanged becomes visible; the whole seeds by extraction from the existing README and codebase, the way rules are extracted — never a big-bang rewrite. The shape, as articulated with the operator 2026-09-01: facets are **flat Markdown files in one folder** — shipped default `.arc/spec/`, the folder settings-overridable like every configured path — with **`shape.json` as the arranger**: grouping, sections and their descriptions, nesting expressed in the JSON structure, never as directories. Prose in Markdown, arrangement in JSON — the items model generalized (order.json is a degenerate shape.json: one ordered, closed, total list). List semantics ride explicit booleans, each defaulting to the weakest claim, since a JSON array is always serially ordered and intent must be declared: `ordered` (sequence-drift is auditable only where order was chosen), `closed` (complete enumeration versus illustrative), `draft` (marked-unfinished; the audit goes advisory, not blocking, on draft sections). The spec audit is a verb — working name **`orient`**, provisional — a registry row today with its taxonomy settings-configurable from day one, and a pure configuration once verbs-as-configurations lands its remaining steps. Still open: the audit's vocabulary (drift taxonomy versus facet meta-rules); and the first extraction's targets — the per-folder ledger READMEs (`.arc/items/`, `.arc/findings/`) are the leading candidates, since each is really doctrine an agent session loads (the agenda contract, the findings provenance rules) that belongs in the one specification rather than scattered as folder files, with the seeded-README-on-first-use behavior in other repos re-examined on the same ground.
