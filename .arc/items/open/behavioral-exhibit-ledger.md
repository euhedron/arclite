A durable, structured home for curated **instances** of an anti-pattern firing — exhibits — distinct from the rules (which state principles), from the code findings ledger (which records repository defects), and from the run log (which already tallies behavioral firing *counts* the moment `live-transcript-auditing`'s `audit-session` runs, exactly as the per-rule (id,hash) rollup tallies code-rule firing — this item does not move or duplicate that quantitative substrate). What has no home is the curated instance that lives outside a run: an exhibit spotted in a live session (the README's behavioral open-question lists these in prose — "reflexive false-efficiency; manufactured urgency; …" — and everything else evaporates with session memory), and a notable `audit-session` finding a human has reviewed and chosen to keep as evidence rather than leave as one row among a run's raw output. This item gives those a home: one record per kept instance, carrying which behavioral rule it exhibits, the located or quoted evidence, and provenance that follows the findings ledger's doctrine (durable records — a session file path and turn, an `arc` run id, a human observation with its source — over agent self-report, which is only a hint). Two write paths, the first usable immediately with no dependency: hand-capture when an instance is spotted live (the operator or a session catches one, as the commissure sessions did for exposition-by-default and workaround-when-the-fix-is-reachable), and promotion of a reviewed `audit-session` finding once that verb lands — the same promote step the code findings ledger already has, carrying the run id as provenance. The payoff is a real corpus where there was prose: `rule-trigger-patterns` mines its literal-phrasing layer from kept instances instead of hand-invented examples, and a human curating the behavioral ruleset reads concrete evidence beside each rule rather than recalling it. The run-log firing *rate* stays the quantitative curation signal (same as for code rules); this ledger is the qualitative evidence beside it. Completion is a defined on-disk ledger with a seed README (the findings ledger's shape, adapted — an exhibit is evidence, not a defect to resolve), hand-capture working end to end, and the promotion contract specified for when `audit-session` exists. Placed with the transcript-auditing cluster it serves: the detector produces instances and logs their firing, this ledger keeps the ones worth carrying, the pattern-mining consumes them.
