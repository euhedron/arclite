Exhibits, composed into findings — not a parallel ledger. Every arc judgment is an audit of some part of something's state at a particular time; what differs between runs is the substrate (code, a session transcript, the agenda) and the anchor, never the machinery. A **finding is judgment + exhibit + provenance**: the exhibit is the evidencing slice of the *input* — the cited construct a code finding points at, the quoted exchange a transcript finding rests on. An exhibit is a *claim*, never a truth: some part of something marked as an instance of a pattern — and it needn't be born inside a run's finding, since a person can flag one directly from their own experience (code, behavior, reality), which enters as a human-origin finding whose judgment is the flagger's (`origin_kind: human`, already in the findings shape). The label is deliberately fluid — "exhibit", "instance", whatever the lexicon declares — a presentation choice over one single-sourced concept, never a hardcoded literal anything dispatches on. The one real asymmetry is how the exhibit travels: *by reference* when the substrate is co-published with the finding (code in the same repo, versioned beside it), *by value* when the substrate lives elsewhere (a transcript in a machine-local store nothing versions and pruning can erase — the finding carries the located quote, which is what makes it shareable and durable). Whether a finding can later "resolve" is likewise not a class property but a verify-time question against whatever state then exists: a codebase evolves; a transcript never grows new versions, so its findings are terminally kept evidence (the existing `indeterminate` verdict already expresses an un-recheckable subject, and the inbox-queued operator-disposition state sharpens that same surface). The flow is the existing one end to end: a run judges its substrate under the selected ruleset and taxonomy (the behavioral set, for session subjects); firing *counts* stay run-ledger-derived (the per-rule (id,hash) rollup, identical for code and behavioral rules); `arc promote` publishes kept findings into `.arc/findings/` with their exhibits and provenance (run id; for a session subject, the store path and location beside the carried quote). The ledger is deliberately a *shareable* surface: recorded instances of real AI output are what operators publish and exchange — the repo findings ledger is the interim publication surface, rulespace the eventual shared home (its recurrence/firing aggregation consumes exactly this substrate), and the arc-driven agent publishes its own instances through the same promote path once the closed loop runs, the operator steering at the top while session discussion stays local. This item therefore delivers the behavioral substrate's entry into the existing lifecycle: the findings README's shape extended for session-subject provenance and by-value exhibits, the promotion contract for `audit-session`'s results once live-transcript-auditing lands, and nothing else new — no folder, no second mechanism. Placed with the transcript-auditing cluster it serves: the detector produces findings with their exhibits and logs their firing, promote keeps the ones worth carrying and sharing, the pattern-mining consumes the carried exhibits.
