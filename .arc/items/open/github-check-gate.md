Run the audit gate as a required GitHub check on this repository: a workflow that runs `arc run audit --backend claude --fail-on-findings` (the backend chosen explicitly — there is no default, and the key the workflow carries is Anthropic's) on pull requests, wired as a required status check on main, so the gate binds at the merge boundary rather than only at each contributor's pre-push hook. (Scope boundary: this item is arclite gating itself; the generalized arc-in-Actions offering for any repo belongs to rulespace-registry.) Prerequisite in place: the `ANTHROPIC_API_KEY` repository secret (set 2026-08-19; verify: `gh secret list --repo euhedron/arclite`). Prerequisite the workflow itself carries: putting `claude` on the runner's PATH — an install step (`npm install -g @anthropic-ai/claude-code`, the CLI's documented setup; verify: <https://code.claude.com/docs/en/setup>, 2026-08-22) plus arc from the release artifacts, both pinnable. To keep the ledger whole, the CI run's record is ingested into the local ledger in the ledger's own native shape — the runner's `runs.jsonl` lines uploaded as a workflow artifact and appended idempotently by run id, no translation — so cloud spend enters `arc usage`. The record keys `repo` to the runner's checkout path, though, so grouping CI and local spend for the *same* project under one lens is a repo-identity reconciliation (the exact-path lens won't match a `/…/runner/…` path to the local one), not a freebie of native-shape ingest — a sub-problem this item names, resolved when the lens carries project identity beyond the raw path. (public-run-record's reduced projection is the *publication* shape, not the ingest shape.) On a public repo the check's log output is itself public: verdict-only until the public-run-record projection lands; the full output shape inherits it.
