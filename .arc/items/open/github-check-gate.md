Make the repository's GitHub audit check (`.github/workflows/audit-gate.yml`, whose steps stay the seed the arc-action composite extracts so the two can't fork) *unbypassable*, and close its ledger gap. The flip: wire the check as a required status check — a branch-ruleset change that is the operator's call once the check proves itself on real PRs; an opt-in enforcement layer, never a replacement, the offline/local hook staying first-class (arc runs with no GitHub at all). A fork's run has no secret access, so the keyed audit can't run from the fork's context. The audit runs from a **trusted-trigger workflow** keyed on the base repository, checking out the fork's PR head and running the audit with the base repo's secret — so the required check always *runs* (never a skip), and the fragile "does a skipped job satisfy a required check" question never arises. The safeguard against the real risk — exposing the secret to untrusted fork code — rests on what arc does: it reads the repo's files and calls the model API, it never executes the audited repo's own code, so the workflow runs *only* arc against the checked-out fork content and never the fork's build, scripts, hooks, or package lifecycle, with the secret scoped to the arc step and least-privilege `permissions:` on the job. The exact trusted-trigger event and checkout mechanics are pinned to cited GitHub docs when built; what stands regardless is that no fork PR merges without that trusted-side audit. The ingest edge: append the workflow's uploaded run-record artifact into the local ledger in the ledger's own native shape, idempotently by run id, so cloud spend enters `arc usage`; grouping CI and local spend under one lens needs a machine-independent project identity, which this item provides as a **committed `.arc/project-id`** — a UUID minted at `arc init`, tracked in the repo, so it travels with the project across machines and the runner's checkout and the operator's checkout resolve the same id. Records carry the id going forward; existing path-keyed ledger records are reconciled in one pass — each associated to the project-id of whatever repo still resolves at its recorded path, and left path-keyed where none does — so the id extends the discovery map's identity rather than duplicating it. Public output stays verdict-only until public-run-record's projection lands, which the full output shape inherits. (Scope boundary: this item is arclite gating itself; the reusable packaging is github-action's, the installable surface github-app's.)
