Run the audit gate as a GitHub check on this repository: `.github/workflows/audit-gate.yml` (landed with this change) runs the hook's own audit invocation — `arc run audit . --backend claude --include src --findings --fail-on-findings`, the backend explicit and the key Anthropic's — on every pull request, with arc installed pinned and checksum-verified from Releases and the backend CLI pinned to the boundary-audited version (`npm install -g @anthropic-ai/claude-code@2.1.216`; setup doc: <https://code.claude.com/docs/en/setup>, 2026-08-22). The workflow's steps are deliberately the seed the arc-action composite extracts, so the workflow and the future Action can't fork. This is an opt-in enforcement layer, never a replacement: the offline/local hook stays first-class (arc runs with no GitHub at all), and what wiring it as a required status check adds — the remaining flip, a branch-ruleset change that is the operator's call once the check proves itself on real PRs — is the unbypassable property: you can't bypass what you chose to enforce. Prerequisite in place: the `ANTHROPIC_API_KEY` repository secret (set 2026-08-19; verify: `gh secret list --repo euhedron/arclite`). Remaining beside the flip: ingesting the uploaded run-record artifact into the local ledger in the ledger's own native shape (appended idempotently by run id, so cloud spend enters `arc usage`; grouping CI and local spend under one lens consumes the project identity device-awareness establishes, since the runner's checkout path is a different machine's path for the same project); and public output stays verdict-only until public-run-record's projection lands, which the full output shape inherits. (Scope boundary: this item is arclite gating itself; the reusable packaging is github-action's, the installable surface github-app's.)
