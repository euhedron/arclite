Make the repository's GitHub audit check (`.github/workflows/audit-gate.yml`) *unbypassable*, and close its ledger gap. The flip: wire the check as a required status check — a branch-ruleset change that is the operator's call once the check proves itself on real PRs; an opt-in enforcement layer, never a replacement, the offline/local hook staying first-class (arc runs with no GitHub at all). A fork's run has no secret access, so the keyed audit can't run from the fork's context. The audit runs on the **`pull_request_target`** event: per GitHub's events reference (<https://docs.github.com/en/actions/reference/workflows-and-actions/events-that-trigger-workflows>, fetched 2026-10-08), it "runs in the context of the default branch of the base repository" — the workflow definition and secrets come from the base, never the fork — and the same page's warning ("avoid using this event if you need to build or run code from the pull request") is the boundary arc's audit sits safely inside: arc reads the repo's files and calls the model API, it never executes the audited repo's own code. So the workflow explicitly checks out the fork's PR head as *data*, runs only the base-pinned arc binary over it — never the fork's build, scripts, hooks, or package lifecycle — with the secret scoped to the arc step and least-privilege `permissions:` on the job. Because the event fires on base-repo context, the check always *runs* for fork PRs (no skip, so no skipped-vs-required question), and no fork PR merges without that trusted-side audit. The ingest edge needs a command, named here: `arc ingest-ci --run <gh-run>` (or a flag on `arc update`) fetches the workflow's uploaded run-record artifact via `gh run download` — GitHub's own CLI, the transport, no new credential path — and appends it into the local ledger in the ledger's native shape, idempotently by run id — a second ingest of the same run is a no-op, a presence-check-before-append this item adds (the ledger is append-only today, with no run-id dedup; the stable-key idempotence is this edge's to build), so cloud spend enters `arc usage`; grouping CI and local spend under one lens needs a machine-independent project identity, which this item provides as a **committed `.arc/project-id`** — a UUID minted at `arc init`, tracked in the repo, so it travels with the project across machines and the runner's checkout and the operator's checkout resolve the same id. Records carry the id going forward; existing path-keyed ledger records are reconciled in one pass — each associated to the project-id of whatever repo still resolves at its recorded path, and left path-keyed where none does — so the id extends the discovery map's identity rather than duplicating it. Public output stays verdict-only until public-run-record's projection lands, which the full output shape inherits. (Scope boundary: this item is arclite gating itself; the reusable packaging is github-action's, the installable surface github-app's.)
