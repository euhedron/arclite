Extract the verb prompts — today inline in Rust (the per-verb role directives, plus the prose shared assembly: the grounding guardrail, the structured/ranked notes) — into dedicated Markdown assets embedded into the binary the way `.arc/rules` are, so a prompt is edited and reviewed as prose rather than as Rust (a rebuild re-embeds it, exactly as with the rules). This makes concrete the roles-as-Markdown step the verbs-as-configurations question names. Then add a dedicated **prompt-quality** meta-ruleset and a pre-push meta-gate that audits the prompts against it when they change — the exact apparatus `rule-quality` already has over `.arc/rules`, dedicated for the same reason: an inline prompt reads as a *string* to the code audit, and prompt-quality is a different intelligence than code-quality (DRY, no-hardcoding). Seed prompt meta-rule: a prompt names the role and the grounds and stops — it does not prescribe the tools, the reasoning, or the thinking-process the model is meant to own; over-instruction usurps the judgment arc's premise reserves for the model, and is brittle across model versions. Prompts are first-class curated artifacts — their articulation is as significant as a rule's, however short. The validation that earns the ruleset (the curation bar — exercise, don't assume) is running prompt-quality against arc's own role directives — does arc over-instruct its own agents? — not a planted rule that only shows the register parses. The meta-audit targets the **fully-assembled prompt** — what the model actually receives — since over-instruction introduced by shared assembly is invisible in a role directive read alone; the authored role is where a finding is then fixed. "Assembled" here is the verb's prompt built with its shipped defaults — the verb's role, the default taxonomy, the standard guardrail and notes — with the run-varying context reduced to its structural shell (section headers, no repo data), since prompt-quality judges the authored-and-assembled template, not any one run's data; that canonical assembly is deterministic and is what the meta-gate renders and audits. The criterion for what becomes editable Markdown versus stays structural glue: a fragment is extracted when it carries role- or grounds-shaping language a reviewer would tune (the grounding guardrail, the structured/ranked notes), and stays code when it is purely mechanical assembly that carries no judgment — the taxonomy block is the clear case, rendered from the configurable taxonomy *data* by `kind_list`, not authored prose, so it is never a Markdown-extracted fragment.
