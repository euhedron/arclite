Accept a `{"rules": [...]}` wrapper object beside the bare list in the JSON rule-pack reader, ignoring unknown sibling keys — a pack file's metadata stays the publisher's concern; arc reads the rules and nothing else. The rulespace registry serves packs as wrapper objects, so a registry-published or sibling-owned pack becomes an arc source verbatim; the bare-list form stays valid. (Scope boundary: a reader affordance, not a schema commitment — arc does not define or validate the wrapper's metadata keys and gains no dependency on the registry's format evolving; a real shared pack contract belongs to rulespace-registry.)
