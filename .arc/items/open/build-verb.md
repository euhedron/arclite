A `build` verb — `arc run build --item <id>`: the selected backend agent implements one open agenda item inside a worktree arc creates for the run — a fresh branch `arc/build/<id>` based on the local head of the default branch (the branch `origin/HEAD` names, falling back to a local `main`; the base is that local branch's head, not the remote-tracking tip, recorded on the run so a local-vs-remote divergence is visible, and the build errors before creating anything when no such branch resolves). The agent is write-granted that worktree and nothing else — a new execution-boundary profile, disclosed in the boundary decomposition like every grant — with read access to the whole checkout, since a build *implements* and reads whatever the item's work touches. What arc assembles deliberately is the *prompt*: the item's own text, the active rules, and the repository's orienting docs (README/specification); that prompt is this verb's, inline like every verb's, and dedicated-prompts later migrates it to Markdown under the prompt-quality gate — a refinement build does not wait on. The run ends by committing the agent's work on the item branch and writing a clean-completion record — but only when there is a change that committed cleanly and verification (build/test where the item's work has it) passed; a run that produces no change, leaves the worktree dirty in a way it can't commit, or fails verification ends *without* a clean-completion record (its errored record names which), so build-management reads it as interrupted, never pending-review. arc never touches the launch working tree and never pushes — the operator reviews the branch and pushes it through the standing pre-push gate like any change, no parallel gate plumbing — and the run record carries the branch, the worktree path, the changeset summary, and the item id. Managing those worktrees over their lifetime (listing, state, resume, discard, cleanup, item resolution) is build-management's, the next item. The operator's directive: items are built through this flow, conversational sessions the bootstrap exception; if driving the external CLIs proves limiting — context control, in-loop auditing — arc owning its own agent loop is the escalation, reached only once that limitation is demonstrated in use; its enabling backend connection is direct-api-backend's, which sits later in the order.
