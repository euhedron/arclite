A `build` verb — `arc run build --item <id>`: the selected backend agent implements one open agenda item inside a worktree arc creates for the run — a fresh branch named for the item (`arc/build/<id>`), based on the repository's current default-branch head, checked out under arc's run area. The agent is write-granted that worktree and nothing else — a new execution-boundary profile, disclosed in the boundary decomposition like every grant. Context is arc-assembled and identical for every build: the src surface the gate audits, the item's own text, and the active rules. The run ends with the changeset committed on the item branch; arc never touches the launch working tree and never pushes — the operator reviews the branch and pushes it through the standing pre-push gate like any change, no parallel gate plumbing. The run record carries the branch, the worktree path, the changeset summary, and the item id; a merged branch resolves its item with the run id in the resolution note; the worktree is removed by an explicit cleanup once its branch is merged or abandoned; an interrupted build leaves the worktree and an errored run record for explicit resume-or-discard. The operator's directive: items are built through this flow, conversational sessions the bootstrap exception; if driving the external CLIs limits it — context control, in-loop auditing — arc owning its own agent loop is the escalation, captured as its own item when confronted.
