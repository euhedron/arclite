A `build` verb — `arc run build --item <id>`: the selected backend agent implements one open agenda item inside a worktree arc creates for the run — a fresh branch named for the item (`arc/build/<id>`), based on the local head of the default branch — the branch `origin/HEAD` *names* (e.g. `main`), falling back to `main` when unset; the base is that local branch's head, not the remote-tracking tip, and the resolved branch name and sha are recorded on the run so a local-vs-remote divergence is visible rather than silently chosen. Checked out under arc's run area. The agent is write-granted that worktree and nothing else — a new execution-boundary profile, disclosed in the boundary decomposition like every grant. Context is arc-assembled and consistent per item — not fixed to `src`: the surface the item actually touches (an item working on `.github`, release assets, or the README/specification gets those; a code item gets the gate's audit surface), the item's own text, and the active rules. The surface is the item's declared or inferred scope, the same scope gate-change-scope gives each step — one definition, not a second. The run ends with the changeset committed on the item branch; arc never touches the launch working tree and never pushes — the operator reviews the branch and pushes it through the standing pre-push gate like any change, no parallel gate plumbing. The run record carries the branch, the worktree path, the changeset summary, and the item id; the lifecycle beyond the run is one deterministic command surface — `arc builds` lists each build worktree with its state, derived, never stamped: *in flight* (a live run marker), *interrupted* (an errored record with the worktree still present), *merged* (the branch tip reachable from the default branch's head), else *pending review*; `arc builds --discard <id>` removes a worktree and its branch, `arc builds --resume <id>` relaunches the run in the same worktree against the same item, and a *merged* build is what `--clean` removes and what resolves the item, the run id in the resolution note. The operator's directive: items are built through this flow, conversational sessions the bootstrap exception; if driving the external CLIs limits it — context control, in-loop auditing — arc owning its own agent loop is the escalation, whose enabling backend connection is direct-api-backend's territory.
