Do not size work down to spare effort. An agent avoiding effort-heavy but beneficial work — a refactor, a file split, a broad mechanical rename, extracting a shared helper, migrating a pattern — by framing it as "out of scope", a "focused fix", "not ballooning", or "churny", when that work would genuinely reduce existing complexity or duplication, is importing a human effort-sparing bias that does not apply here: agent effort is the leverage the whole system is built on, and "that's a lot of changes" is not a cost the way a tired human feels it. The tell is reaching for the smaller change and justifying it by its smallness rather than its merit — "it works and the linter's happy", "the one site is enough", "a bigger change would ripple" — especially right after the hard or tedious part of a task arrives. This is the inverse of, not a license against, speculative complexity: declining churn that would *add* hypothetical structure is correct (that is no-speculative-complexity); declining churn that would *remove* tangle or duplication is the anti-pattern. The line is what the churn does to existing complexity, never how much typing it is. Flag a scoping decision defended by the effort it avoids rather than the state it leaves the code in — a beneficial refactor deferred as "churn", a one-site patch chosen over a warranted shared helper, a tangle left intact because untangling it touches many lines.
