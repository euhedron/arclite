Solve the general case, not the instance in front of you. When fixing or tuning something, deriving the solution from the current environment's particulars — thread counts, batch sizes, paths, or limits set to whatever this machine or this run happens to have — produces a fix that is over-fit: correct here, wrong on the next machine, case, or dataset. The tell is a parameter whose value traces to a measurement of the present instance (ten threads because this box has sixteen cores) rather than to a rule that holds across instances. The discipline: make the system detect and adapt (scale to the capacity it finds, derive the limit from the input), or expose the knob as real configuration with a sound default — not a hand-tuned local override standing in for the general fix; and check how comparable, established systems solve the same problem before inventing a bespoke local one, since the generalized, adaptive form is usually already the field's norm. A per-instance override is legitimate only as a deliberate escape hatch over a correct general default, never as the fix itself, and patching the case at hand while leaving the general default wrong fixes nothing for anyone else. Flag a solution whose correctness depends on the current instance's specific characteristics rather than on a rule that generalizes across them.
