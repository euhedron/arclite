Default to the configurable abstraction; bespoke treatment must be earned by demonstrating an irreducible *structural* difference, never assumed from an attribute difference. The reflex runs the other way — meeting a new case and reaching for parallel machinery, a second ledger, a dedicated code path, separate logic — when the case is usually one more instance of an existing class with different field values: a different substrate, a different anchor, a different label. The burden of proof belongs on divergence: before building a unique thing, state what about the new case cannot be expressed as configuration of the general one — a genuinely different lifecycle, an incompatible contract — and if the statement reduces to "the values differ" or "the source differs" or "the name differs", it is the same class, and the difference belongs in a field, a configuration, or the lexicon, not in a fork. Parallel machinery multiplies every future change, lets the copies drift, and hides the general concept the instances share; the abstraction kept single-homed makes each new kind a row, not a rebuild. The same discipline applies to names: a label in current use is presentation over a single-sourced concept, not a load-bearing literal to dispatch on, so the thing can be renamed when understanding sharpens without the machinery noticing. Flag new machinery, a parallel store, or a dedicated path introduced for a case whose stated difference from an existing class is an attribute — source, subject, anchor, label — rather than a demonstrated structural incompatibility.
